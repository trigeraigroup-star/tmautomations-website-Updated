# TMAutomations Homepage Design

## Scope

The first local draft covers the light hero, a compressed “day in your life” bridge, and the dark How We Work chapter. It includes five future-video placeholders but does not publish, deploy, or create a production Sites project.

## Narrative approach

Use a balanced editorial scrollytelling format. Product-specific HTML copy remains the primary source of clarity; video provides atmosphere. The visitor moves from a familiar day of checking and chasing into a workshop-like process where TMAutomations identifies, develops, launches, and supports a custom automation.

## First viewport

The hero uses the approved H1, “AI Automations, Built Around Your Business.” The supporting sentence explains that TMAutomations takes repetitive work off the client's plate across sales, operations, finance, and admin. A “Book a Call” button is visible without scrolling. Beside the copy, physical work cards demonstrate a real sequence—request, quote, follow-up, complete—rather than a dashboard or abstract AI artwork.

## Story bridge

Compress the supplied pain story into short beats: the owner starts in email, chases quotes and updates, spends the day verifying work, and reaches growth work too late. The section then changes the frame: repetitive chasing, copying, and checking can run in order, with TMAutomations acting as the client's practical partner.

## How We Work

The palette changes to midnight slate with warm amber and linen-like texture. Desktop uses a sticky visual stage with phase copy scrolling alongside it. Mobile uses stacked poster-style placeholders. The four phase names are plain:

1. Identify — See how work really gets done.
2. Develop — Design the right workflow.
3. Adopt — Launch it with your team.
4. Support — Keep it working.

The progress rail uses four accessible segments and updates as each phase reaches the reading position. Scene A supports Identify, Scene B supports Develop, Scene C supports Adopt, Scene D bridges Adopt to Support, and Scene E previews the later timeline climax.

## Visual direction

The page feels like an operations fieldbook becoming an orderly workshop. Warm paper, ruled lines, small registration marks, and physical cards provide character. Avoid glassmorphism, heavy pills, purple gradients, ambient neon, excessive rounded cards, generic icon grids, or decorative robot imagery.

Typography uses Instrument Serif for display text and Manrope for interface and body text, with robust system fallbacks. If remote font delivery is not available, the fallback must preserve hierarchy and readability.

## Motion and performance

Use one orchestrated motion language: gentle upward reveals, a progress rail, and card movement that suggests work advancing. Content is visible by default. `prefers-reduced-motion` disables smooth scrolling, transforms, and nonessential transitions. No real media is loaded in this draft.

## Acceptance criteria

- The approved H1 and plain supporting copy appear above the fold.
- The first draft contains only real founder facts and no invented proof or metrics.
- Four process phases and five scene placeholders are present in semantic HTML.
- The light and dark palettes both meet practical AA contrast.
- Desktop has a sticky process stage; mobile reads as a clean vertical sequence.
- The page remains understandable with JavaScript or animation unavailable.
- A local build completes and a local preview is opened for review.
- No production site is created, saved, or deployed.
